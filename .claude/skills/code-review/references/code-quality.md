## 可読性

### 命名
- [ ] 変数名が内容を正確に表現している
- [ ] 関数名が処理内容を正確に表現している
- [ ] 略語は一般的なもののみ使用（id, url, apiなど）
- [ ] ブール値は `is`, `has`, `can`, `should` で始まる
- [ ] 配列は複数形、単一要素は単数形

### 構造
- [ ] 関数が適切な長さに保たれている（目安: 50行以下）
- [ ] ネストが深すぎない（目安: 3レベル以下）
- [ ] 早期リターンで複雑なネストを回避
- [ ] 関連する処理がグループ化されている

### コメント
- [ ] コメントは「なぜ」を説明（「何を」はコードで表現）
- [ ] 古いコメントが残っていない
- [ ] TODOコメントには担当者や期限がある

## 保守性

### 単一責任
- [ ] 各関数が1つの責務のみを持つ
- [ ] 各コンポーネントが1つの役割のみを持つ
- [ ] ファイルが肥大化していない（目安: 300行以下）

### DRY (Don't Repeat Yourself)
- [ ] 同じロジックが複数箇所に書かれていない
- [ ] 共通処理はユーティリティ関数に抽出されている
- [ ] ただし、過度な抽象化は避ける（3回以上の重複で検討）

### 依存関係
- [ ] 循環依存がない
- [ ] 不要な依存関係がない
- [ ] 外部ライブラリの使用が適切

### 変更容易性
- [ ] マジックナンバー・マジックストリングがない
- [ ] 設定値は定数として定義されている
- [ ] ハードコードされた値がない

## パフォーマンス

### React固有
- [ ] 不要な再レンダリングがない
- [ ] `useMemo` / `useCallback` が適切に使用されている
- [ ] リストには一意の `key` が設定されている
- [ ] 大きなコンポーネントが分割されている

### データ取得
- [ ] N+1問題がない
- [ ] 必要なデータのみ取得している
- [ ] 適切なキャッシュ戦略がある

### 一般
- [ ] 不要なループがない
- [ ] 計算結果の再利用ができている
- [ ] メモリリークの可能性がない（イベントリスナー、タイマーなど）

---

## セキュリティ

### XSS対策
- [ ] ユーザー入力をそのまま表示していない
- [ ] `dangerouslySetInnerHTML` を使用していない（使用する場合は適切にサニタイズ）

### インジェクション対策
- [ ] SQLインジェクションの可能性がない（パラメータ化クエリを使用）
- [ ] コマンドインジェクションの可能性がない

### 認証・認可
- [ ] 認証が必要な操作で認証チェックがある
- [ ] 認可が必要な操作で権限チェックがある
- [ ] センシティブな情報がログに出力されていない

### 機密情報
- [ ] APIキーがハードコードされていない
- [ ] 環境変数を適切に使用している
- [ ] `.env` ファイルがコミットされていない

---

## React/TypeScript固有

### 型安全性
- [ ] `any` 型を使用していない
- [ ] 適切な型定義がある
- [ ] null/undefinedのチェックがある
- [ ] 型アサーション (`as`) の使用が最小限

### Hooks
- [ ] Hooksのルールを遵守している（条件分岐内で呼ばない、など）
- [ ] 依存配列が正しく設定されている
- [ ] カスタムフックが適切に分離されている

### 状態管理
- [ ] 状態が適切なスコープに配置されている
- [ ] 不要な状態がない（派生値は計算で取得）
- [ ] 状態更新が同期的に行われている

### エラー境界
- [ ] 適切なエラー境界が設定されている
- [ ] エラー時のフォールバックUIがある
